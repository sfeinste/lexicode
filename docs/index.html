The thesis

The scarce resource is not agent capability.
It is your attention.

Everything in Lexicode is downstream of that. It never hides what an agent did, it never merges for you, and it never leaves you staring at a spinner wondering whether to intervene.

◧

A board you can rename

Every column carries a fixed category, and automations key off the category — never the name. Rename “Up next” to “Ready” and nothing breaks. Dragging a card never starts a run.

⬡

Runs in real containers

Read-only rootfs, non-root, per-run credentials, a provisioning checklist instead of a spinner, a live activity stream, and steer / stop / take-over at any point.

⚡

Triggers that you can rehearse

A generated editor, a backtest that replays against real history before you enable anything, and eight named outcomes per firing — including the ones where nothing happened.

↻

Loop protection, five layers

On by default. When a chain stops, you get the causal chain rendered — not a throttling notice you have to decode.

▤

A wiki that steers agents

Pages are scoped, owned and expiring agent instructions. Each run shows exactly which pages loaded, why, and what they cost in tokens.

✋

No merge path

Not a permission that is off — an absent capability. The forge port has no merge method, and review submission rejects APPROVE unconditionally.

Runs

Agents are not fire-and-forget

A run is a conversation you can join. When the agent hits a fork in the road it parks and asks — the run stays paused until you answer, and your answer goes straight back into the running session.

  • Live activity stream at three verbosity levels
  • Loaded context, tokens and cost, per run
  • Outputs — branch, PR, wiki proposal — as they appear
  • Send, stop, or take over the container yourself

Triggers

Rehearse the automation before you arm it

WHEN / IF / THEN, generated from the event schema, with loop protection attached to the rule itself. The backtest replays your project's real event history against the rule as written — unsaved edits included. Nothing is executed.

Agents

Guidance is a prompt. Enforcement is not.

A directive tells the agent what to do. Permissions and the network policy decide what it can do — checked in the runtime and the forge adapter, never in prompt text.

  • A reviewer with “edit files” unchecked cannot write code
  • Network policy: none, allowlist, or open — via an egress proxy
  • Append-only directive versions, with the token cost shown

How it works

Ticket → run → pull request → review → you

A ticket can travel from written to reviewed PR waiting for you without anyone touching a keyboard, and every step stays visible and interruptible.

Write the ticket

Description, acceptance criteria, and a delegate. Press D to delegate — starting a run is always an explicit act.

The run happens

A disposable Docker container running Claude Code clones, branches, works, and pushes. You watch it, steer it, or take it over.

A trigger fires

The PR lands, GitHub is polled, and your rule sends a reviewer agent in — with loop protection counting every hop.

The review comes back

Severity-tagged findings on the PR. APPROVE is rejected unconditionally: an agent cannot bless its own work.

The chain stops itself

Five layers of loop protection cap the depth, and the stop is rendered as a causal chain you can read.

You merge

Always. The forge port has no merge method — there is nothing to switch on.

Measured, not claimed

Numbers from a real acceptance run

scripts/s39-acceptance.sh drives the whole product — real binary, real Docker containers, real git over HTTP, the real MCP server, the real GitHub poller, the real trigger engine and the real loop guard — and prints these.

0.55 sConnect a repo → first run in flight (goal: < 5 min)
2 msConfiguring the six-step chain (goal: < 10 min)
42 sThe whole eight-step chain, six runs in six containers
56 sAgent image build, once per machine

Read these honestly: they measure the product's share of each goal, not a human's. The agent in the acceptance run is a scripted stand-in — it clones, commits, pushes and calls the real MCP server, but it does not think, so these are floor values for the orchestration rather than estimates of a real agent's work.
