Agents that ship work while you watch the whole pipeline

Lexicode is a self-hosted workspace where the tickets, the docs, the agents, the triggers and the run logs are one thing. Agents work in disposable Docker containers running Claude Code and hand back a pull request. You merge — always.

Why it exists

The scarce resource is not agent capability.
It is your attention.

Every decision in the product is downstream of that one line.

▲

“Needs you” is never one badge

Four distinct reasons a run stops for a human — question, approval, review ready, failure — each with its own colour, filter and place in the inbox.

⛨

Guidance ≠ enforcement

Directives and wiki pages steer an agent. Tool permissions and network policy constrain it — checked in the adapter, never written as prompt text.

↻

Loop protection you can see

Five layers on by default, and when a cascade stops you get the causal chain rendered, not a throttling notice.

◧

Context you can audit

A per-run panel showing exactly which wiki pages steered the run, why each loaded, and what it cost in tokens.

⌥

No merge path

Not a permission that is off — an absent capability. The forge port has no merge method, and review submission rejects approvals unconditionally.

⬒

Runs in real containers

Read-only rootfs, non-root, per-run credentials, a live activity stream, and steer / stop / take over at any point.

The product

Everything in one workspace

Screenshots from the dashboard the binary serves at 127.0.0.1:7717.

Board

Columns you rename, categories automations key off

Every column carries a fixed category, so renaming “In progress” never silently breaks a trigger. Dragging a card never starts a run.

  • Assignee and delegate are separate fields
  • WIP limits per column
  • Pinned “Needs you” lane above the board

Runs

A live transcript, and an answer box where the question is

A parked run states what it is waiting for. You answer in the step detail and it goes straight back into the running session.

  • Provisioning checklist instead of a spinner
  • Loaded context with per-page token cost
  • Steer, stop or take over mid-run

Triggers

Backtest before you enable anything

The editor is generated from the event catalog, and a backtest replays your rule against real stored history — nothing is executed.

  • Five loop-protection layers, on by default
  • Eight named outcomes per firing
  • Rule health from real firings

Wiki

Docs that expire on purpose

Pages are scoped, owned and dated. A page marked always joins every run's context and shows what it costs against the project's budget.

  • Owner and verified-until per page
  • Backlinks and unlinked mentions
  • Agents propose pages; you accept them

Agents

Permissions with a lock icon, prose without one

A reviewer with “edit files” unchecked cannot write code. That is stronger than telling it not to — and the UI never lets you confuse the two.

  • Four autonomy levels, ordered by risk
  • Per-agent spend, wall-clock and step caps
  • Context preview before a single run starts

Inbox

One place that says what it needs

Answer a question. Fix a failure. Review output. Each row names the reason in words and carries the one action that clears it.

  • Grouped by project
  • Keyboard-first
  • Never a generic “waiting” badge

How it works

Ticket to reviewed pull request, without a keyboard

The canonical chain, configured once and then left alone.

Write and delegate

A ticket with acceptance criteria, delegated to an agent with one keystroke.

Run in a container

Disposable, read-only rootfs, per-run credentials. It clones, works, and pushes.

Trigger the next agent

PR opened by an agent → the reviewer runs and posts severity-tagged findings.

You merge

The loop guard stops cascades at depth 3. The merge button is yours alone.

Quickstart

Three commands

Then create the owner account on the first screen and connect a repository.

# 1. install
make release && LEXICODE_BASE_URL="file://$PWD/dist" sh scripts/install.sh

# 2. check the machine — Docker, ports, disk, credentials
lexicode doctor

# 3. run it
lexicode serve                 # http://127.0.0.1:7717

# just want to look around? a populated demo workspace:
lexicode serve --demo --data-dir ~/.lexicode-demo
